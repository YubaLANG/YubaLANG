# Migrating from YubaLANG 1.2 to 1.3

YubaLANG 1.3 adds expression evaluation and assignment while preserving the
existing command forms. The complete syntax and type rules are in the
[1.3 language reference](1.3-docs.md).

## New syntax

Use `set` to update an existing variable and expressions to combine values:

```hl
define var count: int = 2
set count = count * 3 + 1
text output count
```

The `set` command does not declare a variable and does not change its declared
type. Arithmetic, comparison, and boolean operator precedence is documented in
the language reference.

## Conditions and identifiers

`if`, `elseif`, and `loop while` now require boolean expressions. If older code
relied on collection or numeric truthiness, convert it explicitly with the
`bool` command into a declared boolean variable before using it as a condition.

Variable names must be valid Unicode identifiers. Names such as `bad-name`
and `2count`, which were previously accepted accidentally in some contexts,
now produce an error. Rename them to identifiers such as `bad_name` and
`count2`.

## Compatibility

The existing `arith` commands, four-operand `compare` syntax, and both
`convert value to type` and legacy `convert value type` forms remain supported.
No previously documented command is deprecated in 1.3.

YubaLANG accepts project manifests targeting version `1.2` or `1.3`. New
projects created by YubaLANG 1.3 target `1.3`. The separate YubaPKG project
currently documents importer compatibility with YubaLANG 1.2; check its
compatibility before using a 1.3 manifest with that tool.
